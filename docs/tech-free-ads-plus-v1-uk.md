**Тип:** імплементаційне ТЗ для AI / розробника  
**Мова:** поведінка й чеклісти, **без коду**  
**Джерело продукту:** [reklama-ta-lifetime-pl-uk.md](./reklama-ta-lifetime-pl-uk.md)  
**Дата:** 2 серпня 2026

## 1. Мета

Перевести мобільний додаток на модель:

1. **Free** — увесь навчальний контент і тренувальні режими відкриті; показуємо interstitial-рекламу за правилами нижче.
2. **Plus** — разова покупка назавжди (**24,99 zł**): **без реклами** + **AI-чат** по питаннях.
3. Прибрати старі hard-gate на практиці (помилки, пастки, SRS тощо) і денний ліміт питань.

Платіж = комфорт + AI, **не** «відкрий іспит / помилки».

## 2. Scope / Out of scope

### В scope (v1)

- Mobile (Expo Router app у `mobile/`).
- Entitlement «Plus» vs Free.
- Політика interstitial ads + точки виклику.
- Зняття premium-заглушок з режимів практики (див. матрицю).
- Soft-gate на **повтор** іспиту (реклама або Plus).
- Оновлення paywall copy / comparison / i18n (PL, UA, EN).
- Прибрати продуктову залежність від ліміту 20 питань/день і free AI-квоти.
- Аналітичні події для ads / paywall / gate.
- Feature flags: ads / purchase можна вмикати окремо.

### Out of scope (v1)

- Нові акаунти AdMob / RevenueCat / нові SKU в сторах (якщо ключів немає — graceful stub; поведінка продукту все одно має працювати).
- Підписки, кілька тарифів, sprint packages.
- School codes як спосіб видати Plus (не чіпати B2B логіку глибоко; на paywall не промотувати як основний шлях).
- Rewarded ads «за практику» / банери на питаннях.
- Offline як Plus-фіча (не обіцяти в UI).
- A/B інфраструктура (лише константи, які легко змінити вручну).
- Android/iOS store listing, ASA кампанії.

## 4. Entitlements

### Визначення Plus

Користувач має Plus, якщо виконується **будь-що** з:

1. Dev override / debug toggle (для QA).
2. Активна покупка через існуючий RevenueCat / store entitlement (aliases на кшталт `premium_access`, `plus`, `ai_question_chat` — узгодити з тим, що вже є в клієнті).

Інакше — Free.

### Похідні правила

- **Показувати ads** ⟺ користувач **не** Plus **і** ads увімкнені прапорцем **і** є можливість показати креатив.
- **AI доступ** ⟺ Plus. Без денної free-квоти.
- School / remote entitlements **не** розширювати в рамках цієї задачі (не ламати існуюче, але Plus для v1 = purchase + dev).

### Прапорці (концептуально)

- `enableAds` — чи взагалі намагатися показувати рекламу.
- `enablePlusPurchase` — чи активна кнопка покупки (якщо ні — paywall з поясненням, без падіння).
- `devPlusAccess` — форс Plus локально.

## 5. Що зняти з Premium (обов’язково)

Пройти UI і прибрати hard paywall + `premium` badge для:

| Екран / модуль | Режим / дія |
| -------------- | ----------- |
| Home (`(tabs)/index`) | Плитка «Помилки», плитка «Пастки» |
| Learn (`(tabs)/learn`) | Помилки, Розумні повторення, Пастки |
| Trainer modes | `wrong_answers`, `weak_spots`, `high_points` |
| Practice empty state | Пастки, Розумні повторення |

Після змін: клік відкриває відповідний режим **без** `/paywall`.

**Залишити gate:**

- Вхід у AI-чат → paywall з `feature=ai_question_chat` (або еквівалент), якщо немає Plus.
- Повтор іспиту з результату → існуючий soft-gate (реклама / Plus), див. §7.

**Перевірити й прибрати продуктову логіку:**

- Будь-які перевірки денного ліміту практики (20/день), UI «ліміт вичерпано», редірект на paywall через ліміт.
- Free AI daily quota (8 повідомлень) — AI або повний доступ (Plus), або paywall.

Константи-ліміти можна залишити в config як deprecated / невикористовувані, але **жоден user flow не повинен на них опиратися**.

## 6. Політика реклами (поведінка)

### Формат

- Тільки **interstitial video** (повноекранне).
- Без банерів на екрані питання.
- Без окремого resume-тригера з фону (якщо вже є listener «після 10 хв у фоні» — **вимкнути / не викликати** в v1).
- Немає креативу / SDK вимкнений / Plus → **тихий skip**, навчання не блокувати.

### Глобальні обмеження (завжди)

Перед показом перевірити:

1. Користувач не Plus.
2. Ads увімкнені.
3. Не на забороненому маршруті/стані.
4. Session cap: не більше **6** показів за навчальну сесію.
5. Реклама реально готова до показу.

**Заборонені стани для будь-якого показу:**

- Активний іспит з таймером / екран питань іспиту.
- Онбординг, логін, реєстрація.
- Paywall, access center.
- AI-чат модалка / екран.

**Скидання сесії ads:** після **30 хв** неактивності (або еквівалент існуючої session reset логіки).

### Тригер A — після кожного іспиту (пріоритетний)

- **Коли:** екран результату іспиту (повний і міні), одразу після завершення сесії.
- **Завжди намагатися показати** (для Free).
- **Ігнорує** cooldown 3 хвилини.
- **Поважає** session cap 6, Plus, no-fill, заборонені стани.
- Не показувати під час таймера — тільки на результаті.
- Якщо паралельно міг би спрацювати practice-тригер — достатньо показу після іспиту (без другого підряд).

### Тригер B — практика: 12 відповідей + 3 хвилини

- **Практика** = будь-яке тренування поза іспитом (теми, trainer modes, знаки, помилки, SRS, пастки тощо).
- Відповіді **всередині іспиту не рахуються**.
- Показ, коли **обидві** умови true з моменту **останньої успішно показаної** реклами:
  - відповідей у практиці ≥ **12**;
  - минуло ≥ **3 хвилини**.
- Місце в UX: між питаннями (після feedback / перед наступним питанням), **не** поверх екрану вибору відповіді.
- Якщо 12 відповідей набрались раніше ніж за 3 хв — чекати; показати на першому зручному моменті після cooldown (наступна відповідь / перехід).
- Після успішного показу: лічильник відповідей = 0; оновити timestamp останньої реклами.

### Тригер C — кінець короткої практики

- Користувач закриває / завершує сесію практики з **1–11** відповідями в цій сесії.
- І з останньої реклами минуло ≥ 3 хв.
- І не показали щойно рекламу по тригеру B.
- Тоді **один** interstitial на підсумку / при виході.

### Константи політики (імена — орієнтир)

| Ключ | Значення |
| ---- | -------- |
| practiceAnswersBetweenAds | 12 |
| minMinutesBetweenAds | 3 |
| maxAdsPerSession | 6 |
| sessionInactivityResetMinutes | 30 |
| examResultAlwaysAttempt | true (bypass cooldown only) |

Існуючий модуль політики ads у `mobile/src/features/ads/` — привести до цих правил (не плодити паралельну систему).

### Порядок при збігу тригерів

1. Перевірити Plus / flags / cap / route block.
2. Показати **максимум одну** рекламу.
3. Оновити лічильники.
4. Не показувати другу одразу після першої.

## 7. Іспит: старт vs повтор

| Дія | Поведінка |
| --- | --------- |
| Відкрити іспит з Home / Learn / deep link | Без paywall, без обов’язкової реклами на вході |
| Завершити іспит | Тригер A (результат) |
| «Нова спроба» з результату, Free | Soft-gate: запропонувати подивитись відео **або** купити Plus; після реклами (або no-fill → все одно пускати) стартувати новий іспит |
| «Нова спроба», Plus | Одразу новий іспит, без модалки |
| «Виправити помилки» з результату | Відкрити `wrong_answers` **без** paywall |

Не повертати paywall перед першим/будь-яким стартом симулятора з табів.

- Один lifetime Plus.
- Ціна для відображення (fallback): **24,99 zł** (або рядок з RevenueCat, якщо пакет є).
- Headline / CTA смысл: **без реклами + AI-асистент**, разова покупка назавжди.
- PL орієнтир: `Bez reklam + AI-asystent. Jednorazowy zakup na zawsze.`

### Comparison table — переписати рядки під нову модель

Прибрати або замінити брехливі/застарілі пункти:

- Не показувати Free ✗ на помилках / пастках / SRS.
- Не продавати Offline, якщо фічі немає.
- Не писати «іспит з лімітом» як головну перевагу Premium; замість цього: Free має рекламу / soft-gate на повтор; Plus — без реклами + AI + без gate на повтор.

## 11. Порядок робіт (для AI-агента)

Робити **послідовно**, після кожного блоку — смоук по acceptance.

### Крок A — Відкрити контент

1. Зняти premium/paywall з матриці Free (§5).
2. Прибрати daily question limit з UX і викликів.
3. AI: тільки Plus; прибрати free quota path на клієнті (і на функції, якщо є).
4. Смоук: free-юзер (без Plus) відкриває помилки, пастки, SRS, 3-бальні, іспит.

### Крок B — Політика ads

1. Привести ad-session policy до тригерів A/B/C і констант (§6).
2. Вимкнути resume-from-background як окремий тригер.
3. Підключити виклики: результат іспиту; після відповіді в практиці; кінець короткої сесії.
4. Plus → жодних показів.
5. Смоук: сценарії з §13.

### Крок C — Іспит soft-gate

1. Зберегти/вирівняти модалку «нова спроба»: реклама або Plus.
2. No-fill не блокує старт нового іспиту.
3. Plus без модалки.

### Крок D — Paywall + i18n

1. Переписати comparison і тексти під матрицю (§8).
2. Fallback ціна 24,99 zł.
3. Прибрати offline / «немає помилок у free» / «іспит тільки в premium».

### Крок E — Аналітика + прапорці

1. Події §9.
2. Прапорці ads/purchase/devPlus працюють як описано.
3. Короткий QA-чекліст у PR описі.

## 12. Нефункціональні вимоги

- Реклама **ніколи** не ламає навігацію: fail-open.
- Немає подвійних modal (paywall поверх ads і навпаки в один жест).
- Не показувати ads під час анімації відповіді так, щоб юзер не встиг побачити правильність (після feedback OK).
- Dev: тестові ad unit / stub, якщо `enableAds` і немає прод-конфігу.
- Не чіпати git secrets; не комітити credentials.

## 13. Acceptance criteria (готово, коли)

### Доступ

- [ ] Free відкриває: learning, new, saved, wrong_answers, hard_questions, seen_not_mastered, high_points, weak_spots, exam start.
- [ ] Free **не** відкриває AI — тільки paywall.
- [ ] Plus відкриває AI і не бачить interstitial.
- [ ] Немає UI «залишилось N питань сьогодні» / блокування практики лімітом.
- [ ] На плитках помилок/пасток/SRS **немає** premium badge (або badge лише там, де реально Plus-only — зараз таких practice-режимів немає).

### Реклама

- [ ] Після **кожного** завершеного іспиту Free бачить спробу interstitial на результаті (якщо fill).
- [ ] Два іспити підряд обидва можуть показати рекламу (cooldown не ріже exam trigger).
- [ ] У практиці реклама не частіше ніж раз на 3 хв і орієнтовно раз на 12 відповідей.
- [ ] Під час timed exam — 0 показів.
- [ ] На онбордингу / paywall / AI — 0 показів.
- [ ] Resume з фону **не** показує окрему рекламу.
- [ ] Після 6 показів за сесію — більше не показує, до reset сесії.
- [ ] Plus — 0 показів.

### Іспит повтор

- [ ] Free: нова спроба → gate → реклама (або skip) → новий іспит.
- [ ] Plus: нова спроба одразу.
- [ ] «Робота над помилками» з результату без paywall.

### Paywall

- [ ] Текст = без реклами + AI, lifetime, ~24,99 zł.
- [ ] Comparison не обіцяє offline і не каже, що помилки тільки в Premium.
- [ ] Purchase disabled gracefully, якщо `enablePlusPurchase=false`.

### Регресія

- [ ] Збережені як і раніше відкриваються.
- [ ] Знаки / інші тренування не падають при no-fill.
- [ ] PL/UA/EN рядки без очевидних EN-залишок у ключових paywall/exam gate рядках (або прийнятний fallback через i18n).

## 14. Тест-сценарії для ручного QA

1. **Новий Free:** пройти 12+ питань практики за >3 хв → має з’явитись interstitial між питаннями.
2. **Швидкі 12 відповідей <3 хв:** реклами ще немає; після очікування 3 хв + ще одна відповідь — є.
3. **5 питань і вихід:** якщо cooldown дозволяє — 1 реклама на виході; якщо щойно була — немає.
4. **Повний іспит:** під час сесії 0 ads → на результаті є спроба показу.
5. **Другий іспит одразу:** знову спроба на результаті.
6. **Нова спроба Free:** модалка → watch ad → новий іспит.
7. **Plus (dev override):** немає ads, AI відкривається, нова спроба без модалки.
8. **Клік AI без Plus:** paywall.
9. **Помилки / пастки / SRS з Home і Learn:** без paywall.
10. **`enableAds=false`:** жоден показ, апка користується як раніше.

## 15. Definition of Done

- Усі пункти §13 виконані або явно винесені в follow-up з причиною.
