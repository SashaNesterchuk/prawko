# Prawko — разбор PRD и продуктовая структура

Источник: [Prawko_PRD.docx](/home/lastday/prawko/Prawko_PRD.docx)

## 1. Короткий вывод

Документ описывает не просто "базу вопросов", а мобильный learning product с 3 уровнями ценности:

1. Подготовка к экзамену по официальной базе.
2. Персонализированное обучение через AI и weak spots.
3. Удержание через прогресс, streak, readiness score и короткие сценарии подготовки.

Поэтому в v1 не стоит строить навигацию вокруг "списка функций". Лучше строить ее вокруг 4 пользовательских сценариев:

1. `Главная` — что делать сегодня.
2. `Учить` — проходить темы и вопросы.
3. `Практика` — экзамены, weak spots, saved, exam tomorrow.
4. `Профиль` — прогресс, подписка, настройки, школы.

## 2. Рекомендуемая навигация

### Нижнее меню (4 таба)

1. `Главная`
2. `Учить`
3. `Практика`
4. `Профиль`

### Глобальные слои поверх табов

1. `Экран вопроса` — переиспользуется для learning / exam / weak spots / saved / exam tomorrow.
2. `AI chat` — bottom sheet / full-screen modal поверх вопроса.
3. `Paywall` — модалка или отдельный full-screen flow при упоре в лимит.

## 3. Сколько страниц в MVP

Оптимальная структура для v1:

1. `6` экранов onboarding / access.
2. `4` основных tab screens.
3. `10` внутренних экранов режимов и деталей.
4. `2` глобальных overlay-экрана.

Итого: `22 UI-единицы` для MVP.

Если делать супер-сжатый MVP, можно ужать до `20`, объединив:

1. `Настройки` + `Подписка` в один экран.
2. `Историю экзаменов` + `Review` в один экран с раскрытием.
3. `Exam Tomorrow` в карточку внутри `Практика` без отдельного intro.

## 4. Карта экранов

### A. Onboarding / Access — 6 экранов

1. `Splash / language bootstrap`
2. `Выбор языка`
3. `Выбор категории`
4. `Как устроен экзамен`
5. `Код автошколы` (опционально, можно skip)
6. `Создать аккаунт / начать trial`

Переход:
`Splash -> Язык -> Категория -> Интро экзамена -> Код школы? -> Trial/Auth -> Главная`

### B. Главная — 1 экран

7. `Главная / Dashboard`

Содержимое:

1. progress summary
2. streak
3. readiness score
4. last exam result
5. quick actions: `Продолжить обучение`, `Слабые места`, `Сдать пробный экзамен`, `Экзамен завтра`

Переходы:

1. `Главная -> Учить`
2. `Главная -> Практика / Exam`
3. `Главная -> Weak Spots`
4. `Главная -> Exam Tomorrow`
5. `Главная -> Профиль`

### C. Учить — 2 экрана + shared question screen

8. `Список тематических блоков`
9. `Экран вопроса` (shared)

Что должно быть в `Списке блоков`:

1. блоки: знаки, перекрестки, обгон, пешеходы, первая помощь и т.д.
2. progress bar по каждому блоку
3. completed / in progress state
4. CTA `Продолжить`

Что должно быть на `Экране вопроса`:

1. текст вопроса
2. фото/видео
3. варианты ответа
4. мгновенный feedback
5. explanation
6. bookmark
7. toggle языка вопроса
8. `Ask AI`

Переход:
`Учить -> Экран вопроса -> Следующий вопрос -> Финал блока / назад в Учить`

### D. Практика — 7 экранов + shared question screen

10. `Практика / Hub`
11. `Exam Simulator / Start`
12. `Exam Result`
13. `Exam History`
14. `Weak Spots Overview`
15. `Saved Questions`
16. `Exam Tomorrow`

Переходы:

1. `Практика -> Exam Simulator / Start -> Экран вопроса (exam mode) -> Exam Result -> Exam History / Review`
2. `Практика -> Weak Spots Overview -> Экран вопроса (weak spots mode) -> Weak Spots Overview`
3. `Практика -> Saved Questions -> Экран вопроса (saved mode) / Start mini exam`
4. `Практика -> Exam Tomorrow -> Экран вопроса (exam tomorrow mode) -> readiness result / назад в Практика`
5. `Практика -> Exam History -> Review wrong answers -> Экран вопроса`

### E. Профиль — 4 экрана

17. `Профиль / Stats`
18. `Настройки и подписка`
19. `Каталог автошкол`
20. `Карточка автошколы`

Переходы:

1. `Профиль -> Настройки и подписка -> Paywall`
2. `Профиль -> Каталог автошкол -> Карточка автошколы`
3. `Профиль -> История/статистика режимов` (если нужно — через deep link в Практику)

### F. Глобальные экраны / overlays — 2 единицы

21. `AI Chat`
22. `Paywall`

## 5. Разбор каждой фичи

### 5.1 Onboarding

Где находится:
`До входа в основное приложение`

Сколько страниц:
`4 core + splash + 1 опциональная`

Страницы:

1. splash
2. выбор языка
3. выбор категории
4. краткое объяснение структуры экзамена
5. ввод school code
6. auth / start trial

Переходы:
`Первый запуск -> Язык -> Категория -> Экзамен как работает -> School code? -> Trial/Auth -> Главная`

Комментарий:
это не просто технический onboarding, а момент сегментации пользователя по языку, типу доступа и каналу B2B.

### 5.2 Learning Mode

Где находится:
`Таб Учить`

Сколько страниц:
`1 основной экран + 1 shared question screen`

Страницы:

1. список тематических блоков
2. экран вопроса

Переходы:
`Учить -> Выбор блока -> Вопрос -> Feedback -> Следующий вопрос -> Завершение блока -> Учить`

Комментарий:
это основной daily-use режим. Его нельзя прятать глубже второго уровня.

### 5.3 Exam Simulator

Где находится:
`Таб Практика`

Сколько страниц:
`3-4`

Страницы:

1. старт / описание режима
2. экран вопроса в exam mode
3. результат
4. история / review

Переходы:
`Практика -> Exam Simulator -> Вопросы 1..32 -> Результат -> Review ошибок / История`

Комментарий:
экзамен — ключевой конверсионный и retention-механизм, но не должен быть первым экраном продукта. Сначала пользователь должен увидеть "next best action" на Главной.

### 5.4 Weak Spots Mode

Где находится:
`Таб Практика`, плюс быстрый вход с Главной

Сколько страниц:
`1 overview + shared question screen`

Страницы:

1. weak spots overview с heatmap / очередью
2. экран вопроса

Переходы:
`Главная/Практика -> Weak Spots -> Вопросы -> Обновленный обзор`

Комментарий:
это сильный дифференциатор, поэтому нужен отдельный entry point, но отдельный нижний таб ему не нужен.

### 5.5 Saved Questions

Где находится:
`Таб Практика`

Сколько страниц:
`1 основной экран + shared question screen`

Страницы:

1. список сохраненных
2. режим прохождения сохраненных вопросов

Переходы:
`Вопрос -> Bookmark -> Практика / Saved -> Список -> Повторить / Mini exam`

Комментарий:
логически это не раздел контента, а персональная подборка, поэтому место ей в `Практика`, а не в `Учить`.

### 5.6 Language Switcher on Question

Где находится:
`На экране вопроса`

Сколько страниц:
`0 новых экранов`

Переходы:
`Экран вопроса -> Toggle PL/UA/EN текста -> тот же экран вопроса`

Комментарий:
это встроенная функция интерфейса, а не отдельный сценарий.

### 5.7 AI Question Chat

Где находится:
`На экране вопроса как secondary action`

Сколько страниц:
`1 overlay`

Страницы:

1. AI chat sheet / full-screen modal

Переходы:
`Экран вопроса -> Ask AI -> Chat -> Закрыть -> обратно к вопросу`

Комментарий:
AI не должен жить в отдельном табе. Его ценность контекстная, только рядом с вопросом.

### 5.8 User Profile & Progress

Где находится:
`Таб Профиль`

Сколько страниц:
`2-3`

Страницы:

1. stats dashboard
2. настройки / язык / аккаунт / подписка
3. при необходимости отдельный экран полной статистики

Переходы:
`Профиль -> Детали статистики -> Назад`
`Профиль -> Подписка -> Paywall`

Комментарий:
дневные цели, streak и readiness score частично нужно показывать и на Главной, а глубокую аналитику оставить в Профиле.

### 5.9 Exam Tomorrow Mode

Где находится:
`Таб Практика`, плюс промо-карточка на Главной

Сколько страниц:
`1 overview + shared question screen + 1 result state`

Страницы:

1. intro / ready-to-cram screen
2. экран вопроса
3. readiness result

Переходы:
`Главная/Практика -> Exam Tomorrow -> Сессия 10-15 вопросов -> Readiness score -> Exam Simulator / Главная`

Комментарий:
это ситуативный режим, не постоянный раздел. Поэтому отдельный таб избыточен.

### 5.10 Driving School Directory

Где находится:
`Таб Профиль` как secondary utility, плюс optional link из onboarding

Сколько страниц:
`2`

Страницы:

1. список школ
2. карточка школы

Переходы:
`Профиль -> Автошколы -> Карточка`
`Onboarding -> Нет кода школы? -> Найти школу`

Комментарий:
для v1 это полезный utility/B2B-entry, но не часть ежедневного core loop.

## 6. Оптимальное распределение по разделам

### Главная

Должно быть:

1. приветствие + текущий язык / категория
2. readiness score
3. streak
4. last exam score
5. CTA `Продолжить обучение`
6. CTA `Слабые места`
7. CTA `Пробный экзамен`
8. CTA `Экзамен завтра`

### Учить

Должно быть:

1. тематические блоки
2. прогресс по блокам
3. быстрый вход в незавершенный блок
4. question flow

### Практика

Должно быть:

1. exam simulator
2. weak spots
3. saved questions
4. exam tomorrow
5. history / review

### Профиль

Должно быть:

1. stats dashboard
2. точность по темам
3. streak / activity
4. account
5. language / settings
6. subscription
7. driving schools

## 7. Основные пользовательские потоки

### Flow 1. Первый запуск

`Первый запуск -> Язык -> Категория B -> Как проходит экзамен -> School code? -> Trial/Auth -> Главная`

### Flow 2. Базовое обучение

`Главная -> Учить -> Блок "Знаки" -> Вопрос -> Explanation -> Next -> Завершение -> Главная`

### Flow 3. Пробный экзамен

`Главная/Практика -> Exam Simulator -> 32 вопроса -> Result -> Review wrong answers -> Bookmark / Ask AI`

### Flow 4. Работа над ошибками

`Главная -> Weak Spots -> Персональная очередь -> Вопросы -> Updated score -> Главная`

### Flow 5. Сохраненные вопросы

`Вопрос -> Bookmark -> Практика -> Saved -> Повторить / Mini exam -> Result`

### Flow 6. Срочная подготовка

`Главная -> Exam Tomorrow -> Focus session -> Readiness score -> Запустить Exam Simulator`

### Flow 7. B2B / автошколы

`Onboarding -> School code`  
или  
`Профиль -> Автошколы -> Карточка -> связаться / использовать код`

## 8. Что важно не сломать при проектировании

1. Не делать отдельный таб для AI.
2. Не делать отдельный таб для Saved.
3. Не ставить каталог автошкол в нижнее меню.
4. Не разводить Home и Profile на дублирующие экраны статистики.
5. Не дробить learning mode на слишком много промежуточных экранов.

## 9. Итоговая рекомендация

Для v1 я бы закладывал такую структуру:

1. `4 таба`: Главная / Учить / Практика / Профиль
2. `22 UI-единицы` в полноценном MVP
3. `shared question screen` как центральный reusable экран
4. `AI chat` и `paywall` как глобальные слои
5. `Weak Spots` и `Exam Tomorrow` как режимы внутри `Практика`, но с быстрым входом с `Главной`

Это дает продукт, который выглядит как современный adaptive learning app, а не как "каталог вопросов с подпиской".

## 10. Обновление: Study Plan как core feature

### Почему это может стать основой продукта

Сейчас базовая логика продукта выглядит так:
`учи вопросы -> смотри прогресс -> пробуй экзамен`

Если делать `Study Plan` ядром, loop становится сильнее:
`поставь дату экзамена -> получи план -> выполняй задания дня -> план перестраивается -> дойди до готовности`

Это переводит продукт из категории `question bank` в категорию `guided prep coach`.

### Как это меняет IA

`Study Plan` не должен быть отдельным табом.

Он должен стать логикой поверх текущей структуры:

1. `Главная` превращается в `Сегодня по плану`
2. `Onboarding` получает шаг `Когда экзамен?`
3. `Учить` остается библиотекой тем и ручным режимом
4. `Практика` остается зоной тестов, weak spots и saved
5. `Профиль` получает настройку и пересборку плана

### Обновленный состав экранов

Если `Study Plan` делаем core-фичей, MVP-структура вырастает с `22` до `25 UI-единиц`.

Добавляются 3 новые единицы:

1. `Plan Setup` — дата экзамена / сколько дней / интенсивность
2. `Plan Preview` — что именно пользователь пройдет за выбранный срок
3. `Plan Adjust` — перестройка плана после пропусков или смены даты

### Где находятся новые экраны

#### 1. Plan Setup

Где находится:
`В onboarding`

Что содержит:

1. дата экзамена или срок подготовки
2. сколько минут в день пользователь готов уделять
3. уровень: новичок / уже готовился / пересдача

Переход:
`Выбор категории -> Plan Setup -> Интро экзамена`

#### 2. Plan Preview

Где находится:
`После onboarding / trial, перед первым входом в Главную`

Что содержит:

1. сколько дней осталось
2. сколько тем будет покрыто
3. сколько вопросов, mini tests и full exams запланировано
4. CTA `Начать план`

Переход:
`Trial/Auth -> Plan Preview -> Главная / Сегодня по плану`

#### 3. Plan Adjust

Где находится:
`Из Главной и из Профиля`

Что содержит:

1. пользователь пропустил день
2. пользователь хочет ускорить план
3. дата экзамена изменилась
4. система предлагает: сжать / сдвинуть / пересобрать

Переходы:
`Главная -> Plan Adjust -> обновленный план`
`Профиль -> Plan Settings -> Plan Adjust`

### Как меняется Главная

`Главная` больше не должна быть просто dashboard со статистикой.

Она становится экраном `Сегодня по плану`.

Что должно быть на ней:

1. `До экзамена: N дней`
2. `Сегодняшняя цель`
3. `Сделать минимум за 10 минут`
4. список задач на день
5. прогресс дня
6. readiness score
7. быстрый переход в `Weak Spots`
8. быстрый переход в `Exam Simulator`, если это день контрольной точки

### Новый основной user flow

`Первый запуск -> Язык -> Категория -> Plan Setup -> Как проходит экзамен -> School code? -> Trial/Auth -> Plan Preview -> Главная / Сегодня`

Дальше ежедневный цикл:
`Главная / Сегодня -> Задание 1 -> Задание 2 -> Mini test -> Завершить день -> Следующий день`

### Из чего должен состоять план на день

План не должен быть просто списком случайных вопросов.

Каждый день должен смешивать:

1. `новые вопросы`
2. `повторение weak spots`
3. `1 короткий тест`
4. `периодические full exam`

Пример:

1. 15 новых вопросов по теме `Знаки`
2. 10 вопросов из ошибок
3. mini test на 10 вопросов

### Что еще стоит добавить рядом с Study Plan

Чтобы план не был формальным, ему нужны supporting mechanics:

1. `Диагностический стартовый тест`
2. `Минимум на день` на 10 минут
3. `Автоперестройка после пропусков`
4. `Контрольные точки` каждые 2–3 дня
5. `Readiness score по темам`, а не только общий

### Продуктовый вывод

Если команда хочет более сильное позиционирование, то `Study Plan` — лучший кандидат на роль core feature.

Тогда главный value proposition звучит не как:
`тренируй вопросы к экзамену`

А как:
`скажи, когда экзамен, и приложение построит тебе путь до сдачи`
